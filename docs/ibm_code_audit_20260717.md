# IBM Code Audit — 2026-07-17 (UTC)

Branch: `ibm_fsi` (working tree audited, not just HEAD).
Scope: ghost-cell/image-point IBM subsystem of the cerisse compressible AMReX solver — geometry/BVH, GP chain, inviscid IBM fluxes, viscous IBM fluxes, time loop / FSI / AMR, surface output & load.
Method: 6 parallel subsystem mappers (full-file reads) → cross-lens defect claims → independent verification pass (each claim re-checked end-to-end against the working tree). Only verified findings appear in Section 2; everything refuted is listed in Section 4.

Known/documented limitations (per audit brief) are tagged `known=true` when rediscovered:
(a) flat-wall surface tau (no `-mu*u_t/R`); (b) ghost-cell IBM not discretely conservative at the wall (~+2.5e-5 mass/3000 steps); (c) wall-derivative order capped by interp order; (d) no turbulence wall model; (e) 2nd-order RK time base.

## 2. CONFIRMED DEFECTS (ranked by severity)

### D1 — HIGH — `src/rhs/viscousLES.h:477` — [translation] LES IBM diffusion kernel reads unreconstructed interior-solid cells (never translated to the masked operators of `viscous.h`)

**What is wrong.** `viscousLES_t::cns_diff_ibm` gates near-wall order reduction with only the two face-adjacent cells' GP flag (`viscousLES.h:477` `close_to_wall = marker(iv,1) || marker(ivm,1)`) and then uses the **unmasked** central operators `normal_diff` / `tangent_diff` / `interp` in both branches (`:496-506` order-2 branch, `:523-546` full `param::order` branch).

**Mechanism.** With `ghost_layers` statically fixed to 1 (`ibm_solver.h:323-326`), only the first solid layer is a reconstructed GP. Therefore:
1. In the close_to_wall branch, `tangent_diff<2>` (`diff_ops.H:268-269`) evaluates the tangential derivative at the GP base `iv−ivn` and reads `iv−ivn ± ivt`, which at curved/oblique walls and corners are interior-solid non-GP cells holding stale initial-condition conservative data.
2. With `param::order=4`, a fluid/fluid face one cell off the wall has `close_to_wall=false`, and `tangent_diff<4>` / `normal_diff<4>` (`diff_ops.H:287-300`) read cells two layers into the solid (always non-GP) at **every** wall.
3. Transport coefficients + LES SGS additions (`viscousLES.h:158-163, 213-222`) are computed over the full grown box including solid cells and are never zeroed at non-usable cells — unlike `viscous.h:191-198`.

Interior-solid data is bounded (IC values; solid RHS zeroed), so this produces silently O(1)-wrong wall-adjacent viscous stress and heat flux in every LES + GPIBM run — no NaN, no abort. `viscous.h` fixed exactly this pattern with `ibm_standard_diff_stencil_clean` (`viscous.h:657-683`, full normal+tangential footprint check at `:916`) and masked `normal_diff_ibm2/tangent_diff_ibm2/interp_ibm2` (`:685-784`); `viscousLES.h` was left on the pre-fix pattern. The static_assert at `compute_rhs.cpp:625` blocks only the direct wall-flux mode, not this legacy dense LES path.

**Fix direction.** Port the `viscous.h` pattern: (i) zero `mu/lam/xi` (and suppress SGS additions) at non-usable cells; (ii) replace the two-cell `close_to_wall` test with `!ibm_standard_diff_stencil_clean<order>`; (iii) use the masked `*_ibm2` operators in the near-wall branch. Until then, LES + GPIBM results near walls should not be trusted quantitatively.

### D2 — MEDIUM — `src/tim/advance.cpp:852` (also :767-782, :897-925, :1066; `compute_rhs.cpp:346-351`; `ibm_solver.h:2776`) — [translation] `URHO` used as total density; with PelePhysics `URHO` aliases the first species partial density

**What is wrong.** `src/set/Index.h:24-25` defines `URHO=4; UFS=URHO` — in a USE_PELEPHYSICS build there is **no** total-density component: `cons(URHO)` is ρ·Y₀, and total ρ must be summed over `UFS..UFS+NUM_SPECIES-1` (as `Thermodynamics.h:613-616` and `CNS_K.h:64` correctly do). The end-of-step machinery instead reads `state(URHO)` as total ρ:
1. Fluid positivity check (`advance.cpp:838/852` → abort `:1046`) flags `rho<=0` wherever species 0 is locally absent — Y₀=0 is a perfectly valid state (e.g. fuel absent in oxidizer region) → spurious hard abort "NUMERICAL FAILURE".
2. Pass-2 solid momentum zeroing (`:767-782`) computes ke = 0.5|m|²/(ρY₀) instead of /ρ and subtracts this over-large KE from UET — corrupting solid-cell energy that later feeds FillCoarsePatch/avgDown at regrid.
3. `soft_positivity` clip (`:897-925`) writes rho_new into ρY₀ only, leaving the other partial densities untouched — internally inconsistent state.
4. Non-IBM `check_state` (`:1066` `Schk.min(URHO)`, `:1080-1086` ke/(ρY₀)) has the same false-abort; **verified reachable end-to-end** in a shipped case: `exm/bunsen` (Kee mechanism, CH4 = species 0) has Y_CH4 = 0 exactly deep in the burnt region, no species floor exists anywhere, and `check_state` defaults on → aborts "STATE CHECK FAILED" on a valid state.
Also affected: `compute_rhs.cpp:346-351` (budget "mass" = species-0 only, diagnostic) and `ibm_solver.h:2776` (fixExposedCells donor rejection on ρY₀=0). Single-species builds (URHO = total ρ) are unaffected. The legacy dense IBM flux path compiles for general NCONS, so multispecies + IBM runs reach the IBM sub-items; only the new sparse paths static_assert NCONS==5.

**Fix direction.** Introduce a `total_density(state,i,j,k)` helper (sum over UFS..UFS+NUM_SPECIES-1 under PelePhysics, `state(URHO)` otherwise) and use it in all six sites; the soft_positivity clip must rescale all partial densities proportionally.

### D3 — MEDIUM — `src/ibm/ibm_solver.h:2790` — [conservation] FSI fresh-cell fill invents conserved content; swept fluid→solid cells silently drop theirs — moving-body runs do not conserve even in the fluid interior

**What is wrong.** Every RK abscissa with a moving body, `prepare_ibm_stage` (`advance.cpp:110-111`) calls `fixExposedCells`, whose Jacobi sweep (`ibm_solver.h:2754-2800`) overwrites each newly-uncovered (solid→fluid) cell with the plain arithmetic average of valid face-neighbor donors (`state(i,j,k,n)=sum[n]*inv`, `:2790-2794`) — no donor debit, no bookkeeping. Each uncovering event injects ~one cell-volume of donor-average mass/momentum/energy. Symmetrically, a cell flipping fluid→solid keeps its content as opaque storage (design comment `CNS.cpp:1643-1648`), its RHS is zeroed (`compute_rhs.cpp:1022-1035`) and its momentum zeroed/KE subtracted (`advance.cpp:762-783`); re-uncovering yields a fresh donor average, so the swallowed content is destroyed from the fluid budget. No swept-volume flux term exists anywhere (`src/fsi/` holds only rigid-body kinematics; the conservative_* fields in `ibm_solver_io.h` are surface-load diagnostics). Leak rate ∝ swept volume per step.

**Context.** Fresh-cell non-conservation is an inherent, literature-known property of sharp-interface ghost-cell IBM with interpolative fresh-cell fill; fixing it properly requires a cut-cell/swept-volume or conservative-redistribution formulation this tree does not attempt.
